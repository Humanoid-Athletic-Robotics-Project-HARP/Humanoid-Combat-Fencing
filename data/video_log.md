# Video log

Links to source fencing videos. **Never commit the video files themselves.** Downloads live outside the repo in `$HCF_DATA/videos/raw/<youtube_id>.mp4` (default `~/hcf-data`), with full metadata in `$HCF_DATA/videos/manifest.jsonl`.

Good clip: saber, one fencer visible, steady side-on camera, whole body including feet in frame. See [`docs/plans/2026-11-09-week.md`](../docs/plans/2026-11-09-week.md#finding-videos-what-makes-a-good-clip).

The table is generated by `scripts/hcf scrape log` (after `scripts/hcf scrape run`). Re-running it refreshes the auto columns and adds new videos at the bottom; a row keeps its `#` forever, and the hand-edited columns are never overwritten, so edit them freely. Cells never contain `|` (titles get ` / ` instead), so the table reads the same in any viewer; if you type one inside a cell, the next sync stops and names the line rather than guessing which column it belongs to.

**Auto columns** (refreshed from the manifest on every sync)
- **Video:** `[youtube_id](link)` and title
- **Channel**, **Dur** (`m:ss`)
- **Guess:** motion guessed by the scraper from title/description/search query, plus `footwork` for general footwork videos

**Hand-edited columns** (filled once when the row is created, then yours). An empty cell may be filled later from data the pipeline wrote: by every sync from the screen report, and by `scripts/hcf scrape log --annotate` from `videos/shortlist.json` (best-ranked range), the pose/retarget sidecars and `motions/*.json`. A filled cell is never overwritten; Status moves only off the default `new` (a blank Status stays blank), except that annotate moves `rejected` to `retargeted` when a retarget output or published motion exists, since that is direct evidence the video was usable. Nothing ever moves a row back to `new` or to `rejected` from anything else. Quality is never filled.
- **Motion:** `en_garde`, `advance`, `retreat`, `lunge`, `advance_lunge`, `parry`, `cut` (pre-filled with the guess)
- **Start / End:** timestamp of the usable segment (`m:ss`)
- **Hand:** fencer's sword hand, `R` or `L` (annotate: only when the published motions and every decided `handedness_guess` agree; a hand the cleaner merely detected does not count)
- **View:** `side`, `front`, `angled` (screen views map side → side, front → front, oblique → angled; filled only when 70% of the usable seconds agree on one view, so `unknown` or mixed views leave it empty)
- **Fencers:** number of people in frame
- **Quality:** `A` (ideal), `B` (usable), `C` (backup only)
- **Status:** `new`, `gvhmr_ok`, `retargeted`, `rejected` (annotate: `retargeted` when a clip has a retarget sidecar or a published motion, Notes naming them; `rejected` when the screen found no usable range)
